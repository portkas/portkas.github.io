## 1. [投机解码如何将 vLLM 性能提升高达 2.8 倍 | vLLM 博客](https://blog.vllm.com.cn/2024/10/17/spec-decode.html)

1、原理

- 草稿模型：一个较小，更高效的模型逐个提出令牌；
- 目标模块验证：较大的模型在单个前向传递中验证这些token，确认正确的token并纠正不正确的token；
  - 确认正确的token：通过概率比较，原始模型输出该token的概率大于草稿模型时，保留；
  - 纠正不正确token：是通过什么方法？？？
- 一次传递中处理多个token：同时处理多个token从而减少延迟；

2、vllm中实现投机解码

- 调度器：需要调整调度器以处理单个前向传递中的多个token槽，从而实现同时生成和验证多个token；
- 内存管理器：内存管理器需要处理草稿模型和目标模型的KV缓存，确保在投机解码期间平稳处理；

3、小模型的选择

- 足够小，避免产生显著开销；
- 足够准确，以提供有意义的性能提升；
- 但是由于词汇表的差异，很大程度上会限制投机解码；

4、vllm中支持的投机解码类型

- 基于草稿模型的投机解码
- 提示查找解码（n-gram匹配解码）
  - n-gram：表示连续n个token为一个组合；
  - "The sky is blue."，2-gram示例("The", "sky")、("sky", "is")、("is", "blue")；
  - 在解码前，系统扫描整个提示，提取所有可能的 2-gram 作为键（Key），并记录每个 2-gram 后续的 3 个 token 作为值（Value）。
  - 当大模型生成文本时，检查当前生成的最后两个token是否匹配预存的2-gram键，如果匹配，直接使用对应的值（后续3个token）作为候选输出，无需大模型计算，否则由大模型自行生成下一个token；

1、采样过程

- 用近似模型$M_q$做自回归采样连续生成n个token；
- 把生成的n个token和前缀prompt拼接到一起送到目标模型$M_p$执行一次forward；
- 使用莫表模型$M_p$和近似模型$M_q$的logits结果做比对：
  - 如果对近似模型$M_q$生成tokens都满意（目标模型logits大于近似模型为满意），则目标模型$M_p$直接生成下一个token；
  - 如果发现某个token小模型生成的不好，则从该token之前重新拼接prompt，来生成下一个token；
- 不断重复上述步骤，直到解码结束；

## 5. [Medusa](https://www.cnblogs.com/rossiXYZ/p/18845475)

Medusa 没有使用独立的草稿模型，而是在原始模型的基础上增加多个解码头（MEDUSA heads），并行预测多个后续 token。

整体流程：

- 原始模型最后一层只有一个LM Head，Medusa在该基础又增加了k个Medusa Head；
- 原始LM Head负责预测第t个token，k个Medusa头负责预测t+1~t+k个token；
- Medusa让每个头生成多个候选token而非投机解码那样只生成一个token；
- 每个头都有多个候选token，这样所有头的候选token排列组合，组成不同的序列；
- 不同的候选序列构成一棵树，再通过树注意力机制并行验证；
- 假设增加了4个头，每个头3个候选token，排列组合应该有$3^4$即81个序列需要验证（是这样的嘛？）

疑问：

- 原始模型的LM Head保留，额外又增加了k个Medusa头，原始LM Head每次只输出1个token吗，作用是什么？
- 树注意力机制，是怎么验证的？
- 后面几个head要跨词预测，其准确率应该很难保证吧？
- Medusa更大的优势在于，除了第一次Prefill外，后续可以达到边verify边生成的效果，为什么？？？

文章中重要信息：

- 大模型自身带有一个LM head，用于把隐藏层输出映射到词表的概率分布，以实现单个token的解码；
- Medusa 在主干模型的最终隐藏层之后添加了若干个 Medusa Heads，每个解码头是一个带残差连接的单层前馈网络。
- Medusa 作者观察到，虽然在预测 next next Token 的时候 top1 的准确率可能只有 60%，但是如果选择 top5，则准确率有可能超过 80%。而且，因为 MEDUSA 解码头与原始模型共享隐藏层状态，所以分布差异较小。
- 因为贪心解码的正确率不够高，加速效果不够显著，因此Medusa让每个Head解码top-k个候选，不同head的候选集合组成一个树状结构。为了更高效地验证这些 draft tokens，Medusa根据这些 Head 生成 Token 的笛卡尔积来构建出多个 Token 序列。
- *然后使用Tree Attention方法，在注意力计算中，只允许同一延续中的 token 互相看到（attention mask），再加上位置编码的配合，就可以在不增加 batch size 的情况下并行处理多个候选。这里不懂！*

模型结构：

- Medusa head的输入是大模型的隐藏层输出。这是和使用外挂小模型投机解码的另一个重要不同。外挂小模型的输入是查表得到的token embedding，比这里的大模型最后一层隐藏层要弱的多，因此比较依赖小模型的性能。

```python
class MedusaLlamaModel(KVLlamaForCausalLM):
    """Medusa 语言模型头模块"""
  
    def __init__(self, config):
        super().__init__(config)  # 初始化父类 (Llama 模型)
    
        # 从配置中获取 Medusa 参数
        medusa_num_heads = config.medusa_num_heads  # Medusa 头的数量
        medusa_num_layers = config.medusa_num_layers  # 每个 Medusa 头中的残差块层数
    
        # 设置模型参数
        self.hidden_size = config.hidden_size
        self.vocab_size = config.vocab_size
        self.medusa = medusa_num_heads
        self.medusa_num_layers = medusa_num_layers
        self.base_model_name_or_path = config._name_or_path
    
        # 加载 tokenizer
        self.tokenizer = AutoTokenizer.from_pretrained(self.base_model_name_or_path)
    
        # 创建 Medusa 多头模块
        self.medusa_head = nn.ModuleList([
            nn.Sequential(
                *([ResBlock(self.hidden_size)] * medusa_num_layers),  # 残差块
                nn.Linear(self.hidden_size, self.vocab_size, bias=False)  # 输出层
            )
            for _ in range(medusa_num_heads)
        ])
```

1. **Medusa 头结构**：
   * 每个 Medusa 头是一个序列模块：
     * 包含 `N`个残差块 (`ResBlock`)，`N`由 `medusa_num_layers`配置
     * 最后一个线性层将隐藏状态映射到词汇表大小
   * 整个模型包含 `K`个这样的头 (`medusa_num_heads`)
2. **继承关系**：
   * 继承自 `KVLlamaForCausalLM`，这是一个支持 KV Cache 的 Llama 模型基类
   * 保留了原始 Llama 的所有功能，只是增加了额外的预测头
3. 疑问：
   * 怎么体现的Medusa头是平行关系呢？
   * 只是增加了Medusa头，原始头没有改动；
   * 在哪里体现的每次预留多个token？

```python
def forward(
    self,
    input_ids=None,
    attention_mask=None,
    past_key_values=None,  # KV Cache
    output_orig=False,     # 是否输出原始预测
    position_ids=None,
    medusa_forward=False,  # 是否启用 Medusa 模式
    **kwargs
):
    # 非 Medusa 模式：使用原始模型
    if not medusa_forward:
        return super().forward(
            input_ids=input_ids,
            attention_mask=attention_mask,
            past_key_values=past_key_values,
            position_ids=position_ids,
            **kwargs,
        )
  
    # Medusa 模式
    with torch.inference_mode():  # 推理模式（省内存）
        # 基础模型前向传播
        outputs = self.base_model.model(
            input_ids=input_ids,
            attention_mask=attention_mask,
            past_key_values=past_key_values,
            position_ids=position_ids,
            **kwargs,
        )
  
        # 如果需要原始输出
        if output_orig:
            orig = self.base_model.lm_head(outputs[0])
  
    # 克隆隐藏状态供 Medusa 头使用
    hidden_states = outputs[0].clone()
  
    # 各 Medusa 头前向传播
    medusa_logits = []
    for i in range(self.medusa):
	1. self.medusa记录了有几个Medusa Head；
	2. self.medusa_head[i](hidden_states)将隐藏状态传递给Medusa Head；
	3. medusa_logits存储多个Medusa Head的输出；
        medusa_logits.append(self.medusa_head[i](hidden_states))
  
    # 堆叠所有 Medusa 头的输出
    medusa_logits = torch.stack(medusa_logits, dim=0)
  
    # 根据标志返回不同结果
    if output_orig:
        return medusa_logits, outputs, orig
    return medusa_logits
```

1. **Medusa 模式流程**：
   * **基础模型前向**：
     * 输入通过完整的 Transformer 层
     * 生成最后一层隐藏状态 `outputs[0]`
   * **原始输出计算** (可选)：
     * `output_orig=True`时计算原始 LM Head 的输出
   * **Medusa 头并行预测**：
     * 克隆隐藏状态 (避免原地修改)
     * 每个 Medusa 头独立处理相同的隐藏状态
     * 收集所有头的 logits 输出
2. 疑问
   * self.base_model.lm_head(outputs[0])
   * outputs = self.base_model.model(...)
   * outputs[0]是什么？
3. 输出结构
   * 默认：返回张量 shape `(num_medusa_heads, batch_size, seq_len, vocab_size)`
   * 当 `output_orig=True`：返回元组
     `(medusa_logits, base_output, original_logits)`

### 1. `self.base_model.model()`方法

**输入参数:**

* `input_ids`: 输入 token IDs，形状为 `[batch_size, seq_len]`
* `attention_mask`: 注意力掩码，形状为 `[batch_size, seq_len]`
* `past_key_values`: KV Cache 缓存，用于存储历史计算的 Key 和 Value
* `position_ids`: 位置 IDs，指示 token 在序列中的位置
* `**kwargs`: 其他可能参数（如 `use_cache`, `output_attentions`等）

**输出 (`outputs`):**

* 返回一个包含多个元素的元组（tuple）
* `outputs[0]`: **最终隐藏状态**（last_hidden_state）
  * 形状: `[batch_size, seq_len, hidden_size]`
  * 这是 transformer 最后一层的输出，包含所有位置的特征表示
* `outputs[1:]`: 其他可能输出（取决于模型配置），通常包括:
  * `outputs[1]`: 更新后的 past_key_values（新的 KV Cache）
  * `outputs[2:]`: 如果配置要求，可能包含隐藏状态、注意力权重等

### 2. `self.base_model.lm_head()`方法

**输入:**

* `outputs[0]`: 上述的最终隐藏状态
  * 形状: `[batch_size, seq_len, hidden_size]`

**输出 (`orig`):**

* 原始模型的输出 logits
  * 形状: `[batch_size, seq_len, vocab_size]`
  * 每个位置对词汇表中每个 token 的未归一化分数
  * 这是标准语言模型的输出，用于预测下一个 token

python语法：

1. hasattr()
   * 用于动态检查一个对象是否具有指定的属性或方法。
2. medusa_logits = logits[i, :, : -(2 + i)].contiguous()
   * `logits`是一个三维张量，形状可能为 `[medusa_heads, batch_size, sequence_length]`。
   * `i`选择第 `i`个头。
   * : -(2 + i)从序列维度截取前 sequence_length - (2 + i)个位置（排除末尾的 2 + i个位置）。
   * 确保张量内存连续，提升后续操作效率（如 `view()`）
3. medusa_labels = labels[..., 2 + i :].contiguous()
   * 从标签张量 `labels`中截取与当前头 `i`对应的部分；
   * `...`表示省略前面的维度（如 `batch_size`）。
   * `2 + i :`从序列的第 `2 + i`个位置开始截取到末尾。
4. medusa_logits.view(-1, logits.shape[-1])
   * 将 `medusa_logits`重塑为二维张量，形状为 `[batch_size * sequence_length, num_classes]`，便于计算损失
   * medusa_logits：通常是一个三维张量，形状为 [batch_size, sequence_length, vocab_size]，表示 Medusa 头对每个位置 token 的预测 logits（未归一化的概率分数）。
   * .view(-1, logits.shape[-1])：
   * -1：自动推断该维度的大小，确保总元素数不变。例如，若原张量形状为 [4, 10, 32000]（batch=4，序列长度=10，词表大小=32000），-1会被计算为 4 * 10 = 40。
   * logits.shape[-1]：保留最后一个维度（词表大小 vocab_size），即 32000。
   * 结果形状：[batch_size * sequence_length, vocab_size]（如 [40, 32000]）。
5. medusa_labels.view(-1)
   * 将标签展平为一维张量，形状为 `[batch_size * sequence_length]`。

疑问：

1. 根据代码，为什么预测值（logits）和标签（labels）的截取方向相反（一个排除末尾、一个保留末尾）？
   * 每个头 `i`负责预测未来第 `i+1`个时间步的 token（例如，头0预测 `t+1`，头1预测 `t+2`，依此类推）
   * 预测值，需要基于当前及历史信息生成未来 token 的预测。例如，头 `i`的输入是序列的前 `L - (2+i)`个 token；
   * 标签，需要与预测的未来位置对齐。例如，头 `i`的标签应从第 `2+i`个位置开始，因为前 `1+i`个位置是用于预测更早时间步的（如头 `i-1`预测 `t+i`）。
   * 数学关系，如序列长度为L：
     * 头 `i`的预测值覆盖 `[0, L-(2+i))`，共 `L-(2+i)`个 token。
     * 头 `i`的标签覆盖 `[2+i, L)`，共 `L-(2+i)`个 token。
       两者长度一致，确保逐位置对齐计算损失。
   * `logits[i, :, : -(2+i)]`排除了末尾 `2+i`个位置，因为头 `i`需要预测的是 `t+1`到 `t+i+1`的 token，其输入序列必须不包含这些未来位置的信息。
